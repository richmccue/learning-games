# Meditation Timer

A build of the plan in `meditation-timer-plan.md`: an offline, installable
meditation timer in plain HTML, CSS, and JavaScript, no framework, no build
step.

## Deploying to GitHub Pages

1. Push this whole folder to a repo (or a `meditation-timer/` subfolder of
   one), keeping the relative structure below intact.
2. Turn on GitHub Pages for that branch/folder in the repo settings.
3. Visit the page once over HTTPS so the service worker installs, then it
   works offline and can be added to the home screen.

```
meditation-timer/
├── index.html              Markup, styles, and app logic
├── sw.js                   Service worker for offline caching
├── manifest.webmanifest    Install metadata
├── make_icons.py           Regenerates the icons below (Pillow)
└── icons/
    ├── icon-192.png
    ├── icon-512.png
    ├── icon-maskable-512.png
    └── apple-touch-icon.png
```

## What's implemented

All of F1 to F8 from the plan: offline install, start/end/interval chimes,
adjustable and remembered session length, the top-3 popular-length chips,
the settle-in countdown, pause/resume, and end-early with confirmation. The
timing engine, the interval-chime math, the pause/resume accounting, and the
missed-chime/backgrounding behaviour all follow section 7 of the plan
(timestamp-based, not tick-counted). Home, Session, and Settings match the
three-screen layout in section 5, with the Session screen always dark
regardless of system theme. Storage matches the `meditationTimer.v1` schema
in section 8.

## Two deliberate deviations from the plan, both worth a look

**Chimes are synthesized, not recorded.** The plan calls for a CC0 singing-bowl
recording from a site like Freesound, trimmed and exported as MP3. I built
this without a network connection, so instead the chimes are generated at
play time with the Web Audio API (a few detuned sine partials with an
exponential decay, quieter and simpler for the interval chime). The code is
already set up to prefer real recordings if you add them: drop
`chime.mp3` and `chime-soft.mp3` into an `audio/` folder next to `index.html`
(matching the plan's file structure) and add both paths to the `ASSETS` list
near the top of `sw.js`. The app tries to fetch and decode those files on
first audio use and only falls back to the synthesized bell if they're not
there, so no code changes are needed beyond that. The synthesized version is
pleasant but a real recording will sound noticeably better and is worth
doing before this goes in front of real users. The About screen's credit
line updates itself automatically depending on which one is active.

**The iPhone silent-mode fix is unverified.** `navigator.audioSession` is
applied where supported, per section 6, but I have no way to test it on
real iOS hardware in this environment. Section 12's test plan flags this
specifically ("turn on silent mode on an iPhone and tap Test chime") and
it's the one item I'd treat as unconfirmed until someone runs it on a phone.
If chimes stay muted in silent mode on the device you test with, the plan's
own fallback note applies: the "On iPhone, turn off silent mode" message
already shows next to Test Chime on iOS, so nothing will fail silently.

## Everything else worth knowing before you test

- No audio files are required to try it, since the synthesized chime is the
  default.
- The wake lock falls back to the muted-canvas-video technique (the same
  approach NoSleep.js uses) on browsers without the Wake Lock API, so no
  external library or video asset is needed.
- Icons are generated by `make_icons.py` (needs Pillow: `pip install
  pillow`). Rerun it if you want a different glyph or palette; the brass
  bowl-and-ripple motif is defined right at the top of that file.
- I have not been able to run this on a physical iPhone or Android device,
  so section 12's full test plan (airplane mode, auto-lock timing, phone
  calls mid-session, Low Power Mode) still needs a real-device pass before
  you'd call this done.
